## Safety invariants implemented

### Production smoke

`scripts/prod-e2e.mjs` is now a read-only smoke. Its network allowlist contains only:

- `GET /`
- `POST /api/admin/session/pin` (authentication lifecycle only)
- `GET /api/admin/session`
- `DELETE /api/admin/session` (authentication lifecycle only)
- `GET /api/admin/vip-floor`

It verifies the unauthenticated guard, Basic + Owner PIN login, cookie persistence, current business-date
read, alternate-date read, local search behavior, logout, and post-logout rejection. It has no command
endpoint, reservation selection, or business mutation code. Output contains only stage booleans and
aggregate row counts; it does not print the origin, credentials, PIN, cookies, reservation identifiers,
customer fields, or response payloads.

### Staging mutation harness

`scripts/staging-mutation-e2e.mjs` is separate from the production smoke and requires all of:

- a non-production staging/preview hostname, or an exact hostname allowlist;
- the explicit confirmation value `GHOST_VIPAPP_ALLOW_STAGING_MUTATION=E2E削除可`;
- Basic credentials and an Owner PIN supplied through the process environment;
- a fixture API response with marker `E2E削除可`;
- `notificationMode: "disabled"` and `cleanupRequired: true`.

The harness creates its own fixture, obtains that exact reservation and its current version from the
board, performs one idempotent note mutation, re-reads the board, proves the version advanced, verifies
the returned audit ID, and checks cleanup orphan counts for reservation, customer, block, Waitlist,
outbox, and audit data. Cleanup and logout run in `finally`, including on mutation failure. The canonical
production hostname is rejected before any fetch.

The required staging fixture and audit routes default to:

- `POST /api/admin/e2e/fixtures`
- `GET /api/admin/e2e/fixtures/:fixtureId/audit`
- `DELETE /api/admin/e2e/fixtures/:fixtureId`

These can be changed to same-origin relative paths through the documented script environment variables.
The harness is executable only after the Data/API lane provides these isolated staging-only contracts.

Non-secret configuration variables are `GHOST_VIPAPP_STAGING_ORIGIN`,
`GHOST_VIPAPP_STAGING_HOST_ALLOWLIST`, `GHOST_VIPAPP_PRODUCTION_HOSTS`,
`GHOST_VIPAPP_STAGING_FIXTURE_PATH`, and `GHOST_VIPAPP_STAGING_COMMAND_PATH`. Secrets remain environment
inputs and must not be written to command history, artifacts, or repository files.

### CI and artifact safety

`.github/workflows/ci.yml` uses Node 24 and the lockfile, then runs lint, typecheck, unit tests, contract
tests, build, and the artifact safety scan. The scan covers conventional test artifact roots and detects
Authorization values, session cookies, numeric Owner PIN values, email addresses, and Japanese phone
numbers. Finding output uses a hash of the artifact path rather than logging a potentially sensitive
filename.

# TableCheck型 VIP Floor Board 再現調査・実装前仕様

- 調査日: 2026-07-14 JST
- 対象: `http://localhost:3000/admin/vip-floor`
- フェーズ: 調査・仕様化のみ（実装未着手）
- 目的: TableCheck Managerのフロア運用を、画面構成だけでなく予約状態、配席、時間軸、順番待ち、ブロック、顧客・決済・操作履歴まで再現できる粒度に分解する

## 1. 結論

TableCheckのフロア画面は、単独の座席マップではない。次の4画面が同一営業日・同一予約データを別の作業軸で見せる、一体型の予約台帳である。

1. **フロア**: 現在の席状態、来店進行、配席、ウォークイン、順番待ち
2. **チャート**: テーブル×時間の空き、回転、滞在時間、予約ブロック、未配席
3. **リスト**: 予約の検索、ソート、メモ確認、出力
4. **予約詳細/予約フォーム**: 顧客、予約、支払、画像、操作履歴、POS、連絡、編集

現行GHOST VIP Floorは、大判VIPマップと右インスペクタを中心に、配席、チェックイン、確認、キャンセル、ウォークイン、着席延長、決済証跡を実装している。しかし、TableCheck再現に必須となる**時間軸チャート、複数回転、未配席、ブロック、順番待ち、詳細な来店進行ステータス、顧客台帳、監査履歴、スタッフテーブル割当**が不足している。

実装を始める前に、見た目の作り直しではなく、予約・席・時間・状態のドメイン契約を拡張する必要がある。

## 2. 再現範囲の定義

### 2.1 忠実に再現するもの

- 画面の情報アーキテクチャ
- グローバルナビ、営業日ヘッダー、営業区分切替
- フロア/チャート/リストの切替と各画面の主従関係
- テーブルと予約の情報密度
- 予約ステータスと色の同期
- 予約作成、編集、キャンセル、配席、再配席、未配席化
- ドラッグ＆ドロップとタッチ代替操作
- ウォークイン、順番待ち、通知、ブロック
- 顧客、予約、支払、画像、操作履歴の詳細パネル
- タブレット/モバイルでの操作モデル
- 操作権限、確認、エラー、警告、監査表示

### 2.2 そのまま複製しないもの

- TableCheckのロゴ、商標、固有コピー
- TableCheck固有のアイコン画像や添付画像
- TableCheckのソースコード、非公開API、非公開データ
- GHOST OSAKAに存在しないレストラン固有項目の無条件な露出

### 2.3 推奨する忠実度

**構造・操作・密度はTableCheckに忠実、ブランド表現はGHOST OSAKA**とする。

- TableCheckの白/紫または標準ダーク配色をそのままコピーしない
- GHOSTの黒紫ラッカー、シャンパンメタル、VIPフロア画像を使用する
- ただし、装飾を増やしてTableCheckの情報密度や操作速度を損なわない
- generic SaaSカード、ガラス、グラデーションオーブ、巨大余白は使わない

## 6. チャート画面仕様

### 6.1 役割

フロアが「現在の状態」を見る画面なのに対し、チャートは**テーブル×時間で空き、回転、重複、滞在時間を判断する画面**である。

```text
┌────────────────────── Chart toolbar ─────────────────────────┐
│ fit width │ settings │ Reservation/Block/Assignment │ Online │
├───────────┬──────────────────────────────────────────────────┤
│ section   │ 15:00 16:00 17:00 18:00 19:00 ...               │
│ allocation├──────────────────────────────────────────────────┤
│ table/cap │          reservation bar                         │
│ table/cap │    reservation bar                               │
│ table/cap │                       reservation bar             │
├───────────┴──────────────────────────────────────────────────┤
│ No-show │ Cancelled │ Deleted │ Unassigned                   │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 必須要素

- 営業シフトに基づく時間軸
- セクション見出し
- テーブル名、配席可能人数、喫煙、オンライン不可、メモ
- 現在時刻の赤い縦線
- 予約配分の混雑率ゲージ
- 予約バー（人数、顧客、フラグ、メニュー、ステータス等）
- 予約/ブロック/割当モード
- オンライン受付の営業区分別ON/OFF
- 無断キャンセル、キャンセル、削除済み、未配席の下部トレイ

### 6.3 チャート操作

- 空きセルを選択して予約/ウォークイン/ブロック作成
- 予約バーを縦ドラッグしてテーブル変更
- 予約バーを横ドラッグして開始時刻変更
- 予約バー端をドラッグして滞在時間変更
- 予約同士を重ねてテーブル交換（設定/連携制約あり）
- 未配席トレイから予約を選び、その場で配席
- 画面幅に営業時間全体をフィット

### 6.4 予約ブロック

- オンラインのみブロック
- 全てブロック
- 日付、時間、営業区分、テーブル、メモ
- 繰り返しブロック
- ブロックを削除して予約作成
- ブロックは予約配分に数えない
- オンラインブロックと全ブロックは異なる色

### 9.2 GHOSTで必要な対応方針

| TableCheck概念 | 現行GHOST | 判定 |
|---|---|---|
| 仮予約/未処理 | pending / pending_card_setup / pending_deposit | 部分対応 |
| 確認/確認済み | confirmed | 区別なし |
| 到着/一部到着 | なし | 新規必要 |
| 順番待ち/通知済 | なし | 新規必要 |
| ご案内済み | checked_in | 概ね対応 |
| サービス進行 | なし | VIP運用に必要か要決定 |
| 会計依頼/会計済み | Stripe証跡のみ | 予約状態との統合が必要 |
| リセット中/済み | なし | 席解放/次回転に必要 |
| キャンセル | cancelled | 対応 |
| 無断キャンセル | なし | 新規必要 |
| 削除済み | なし | 新規必要 |

状態は色変更だけでなく、次を変える。

- フロアのテーブル表示
- 右リストの所属タブ
- チャート下部トレイ
- 顧客の来店/キャンセル集計
- オンライン在庫
- 通知送信
- 席の解放時刻

## 10. 順番待ち、ウォークイン、スタッフ

### 10.1 ウォークイン

- 当日のみ
- 営業開始後に利用可能
- フロアでは空テーブルを選択して作成
- チャートではテーブル×時間セルを選択して作成
- 未指定時は選択テーブルの最大人数
- 店舗/営業シフト既定の滞在時間を採用
- 作成後は「ご案内済み」相当

### 10.2 順番待ち

- 当日のみ
- 人数、既存顧客、案内予想時間、通知先を登録
- SMS到達確認
- 席確保後にゲスト呼び出し
- 呼び出し回数1-5回、間隔1分-3時間
- 通知後は「通知済」
- 来店後にテーブルと状態を設定して予約タブへ移動
- キャンセル/期限切れ処理

### 10.3 スタッフテーブル割当

- 営業区分ごとに担当を割当
- スタッフ検索、スタッフ選択、複数テーブル選択
- テーブル→スタッフ、スタッフ→テーブルのどちらの順でも割当可能
- 担当変更、部分変更、解除
- スタッフ名、色、アバター
- 担当テーブル数/最大収容人数
- 選択営業区分の予約組数/人数、今後の予約
- フロア、予約リスト、予約詳細へ担当表示
- 表示ピンで名前を隠し色だけにできる

## 11. モバイル/タブレット

### 11.1 タブレット

- デスクトップと同じ左ナビ+上部バー
- フロアは左キャンバス+右予約リスト
- 長押しでホバー相当の情報を表示
- ドラッグ操作を維持
- タッチ対象は44px以上

### 11.2 モバイル公式アプリ

TableCheck Managerの公式スクリーンショットでは、デスクトップを縦積みしていない。

- 上部: 前日/翌日、Today、営業区分
- 本体: 幾何学マップではなく、テーブルを密なグリッドセルへ簡略化
- 色付きセルにテーブル名、予約時刻、人数を表示
- 下部: 「予約を見る」「順番待ちに追加」等の固定アクション
- 最下部: 作成、リスト、フロア、メニューのボトムナビ
- 予約作成はステップ式
- 予約一覧は固定行高の表形式

GHOSTのモバイル版も、現在のデスクトップ2カラムを単純に縦積みせず、この専用モードを採用する。

| per-date/per-shiftオンライン受付切替なし | 売止めが粗い | P1 |
| テーブルロックなし | 指定席を誤移動しうる | P1 |
| 予約リスト出力なし | 紙/CSV運用に対応できない | P2 |
| モバイル専用IAなし | 縦積みが長く現場速度を落とす | P1 |

### 12.3 実装前に解消すべき既存契約の注意

- `VipStatusSeat.reservation` は単一予約。TableCheck再現には時刻順の複数予約配列が必要。
- 予約は `seats[]` を持つが、現行割当操作が「追加/置換/交換/解除」を明確に区別していない。
- ウォークインUIは任意の開始/滞在分を受け付けるが、本番API送信時は最寄りの標準slotへ寄せている。
- 予約メモは端末localStorageのみで、スタッフ/端末間共有されない。
- 着席延長UIは1/2/3時間を提示する一方、APIは15/30/60/120分のみ許可し、180分を拒否する。
- 予約キャンセルは即時実行で、理由/返金/確認の段階がUIにない。
- 45秒ポーリングのため、複数端末の同時操作競合を即時検知できない。
- `operations` はグローバルfeature flagで、TableCheckの営業日/営業区分別オンライン受付とは別物。
